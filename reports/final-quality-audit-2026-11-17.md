## 三、从专项脚本升级为全书完整性门禁

新增 `scripts/audit-book-integrity.mjs` 和 `pnpm docs:audit-book`，并将其纳入 `pnpm docs:check`（因此每次 `docs:build` 都会运行）。

**检查项：**

1. 遵循 `config/chapters.json`，验证 **32 个内容单元**的 PDF 页码范围**从 1 到 472 连续、无重叠/空洞**；64 个语言源文件存在并声明正确物理页范围。
2. 为各编号章节和书末参考文献固定双语文献条目数，检查条目后的**孤立分页续行、游离标题/URL**；不是仅统计 `- ` 项数量。
3. 检查分页页锚的 HTML ID 不重复；解析本地 `#page-n-0` 引用，验证它指向实际存在的来源文件与页锚；其他标题锚点与资源仍由已有站点构建和 dist 检验。
4. 把第 23 章“书末参考文献”与 `docs/90-references/` 的独立文件链接作为结构条件，避免误认为第 23 章没有书目。
5. 检查明显损坏的 Unicode 替代符和合并冲突标记；对部分原始 PDF 页锚缺少独立展示标记，仅做**非阻断提示**，不能凭推测修改图文页边界。
6. 打印实际检出的文件、页、参考文献、插图、本地页锚回链和外部链接数量，明确其仅是**本地文本格式与链接有效性**的数量。

运行建议：

```bash
pnpm install --frozen-lockfile
pnpm docs:audit-book
pnpm docs:audit-structure
pnpm docs:audit-source
pnpm docs:audit-formula
pnpm docs:build
pnpm docs:check-dist
```

**失败策略：**必须拦截书目断裂、数量偏移、错链、缺文件和元数据页码不一致；确实存在的原始 PDF 夹带行内锚点不足可以报告但不擅自补写。网站构建通过不意味着研究论文已被完整验证。

### 首次全书门禁真实扫描统计

GitHub Actions 工作流（PR #29，初次可运行检查）执行 `pnpm docs:check` 中的独立 `docs:audit-book` 已通过：**32 个映射单元、64 份双语源文件、472 页连续覆盖、2,004 条中英文书目项（每种语言 1,002 条）、236 个图像引用（每种语言 118 个）、804 个页锚 ID、5,351 个本地源页链接引用**。其中额外记录到的 **178 个外部 Markdown 链接**仅指在此脚本特定正则语法下识别到的链接，**不涵盖所有 `<https://...>` 自动链接，更不表示远程地址逐项可访问**。独立的站点资源校验还在 `docs:check` 中确认源目录有 **120 个资源文件**。

**36 条非阻断检查警告**均来自同一类差异：**18 个编号章节 × 两种语言**的页面锚点数量小于 manifest 所声明的 PDF 物理页跨度。差异示例：第 14 章为 **2/6**、第 2 章为 **29/34**、第 12 章为 **18/22**；其他同类章节包括 **1、3、4、5、8、9、10、11、13、15、16、17、20、21、22**。这表示单独可见的页锚数量不足，**不等于正文页面肯定丢失或对应文字未被保留**；同样不应把每个 page-* 的“存在”误当作源 PDF 所有图文完整。待取得原 PDF 后，应逐一复核缺口并区分页标省略、内嵌锚点、跨页正文和真正的缺页。此类警告不通过猜测补造物理页边界来消除。

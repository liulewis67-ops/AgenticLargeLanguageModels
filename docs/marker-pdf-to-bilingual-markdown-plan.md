# PDF 转 Markdown 双语实施方案

- 项目：AgenticLargeLanguageModels
- 输入 PDF：`AgenticLargeLanguageModels.pdf`
- PDF 转换工具：[datalab-to/marker](https://github.com/datalab-to/marker)
- Python 依赖管理：[`uv`](https://docs.astral.sh/uv/)
- 交付形式：按章节和处理阶段分目录保存 Markdown；每个内容单元提供英文版 `-en.md` 与中文版 `-zh.md`
- 方案范围：本文规定后续实施步骤与验收要求；不包含本次执行转换

## 1. 目标

使用 Marker 将 PDF 内容提取为 Markdown，依据 PDF 书签、目录和正文标题划分内容单元。每章独立保存，较长章节可按页段分批处理后再整理；不将整本书合并成单个 Markdown 文件。最终内容提供中英文两版，并支持从索引跳转到章节及章节间导航。

处理流程：

```text
PDF 盘点 → 章节与页码映射 → 环境和样章验证 → Marker 分批提取
       → 章节整理与原文校对 → 中英文稿生成 → 链接及内容验收
```

## 2. 目录和文件命名

正式文稿按内容单元分目录；转换、翻译和校验的中间产物按阶段分目录保存，避免与正式稿混杂。英文文件与中文文件使用相同的稳定主名，仅以 `-en.md`、`-zh.md` 区分。目录页面与章节文件之间使用相对路径链接，便于在本地和代码托管平台浏览。

```text
项目根目录/
├── AgenticLargeLanguageModels.pdf
├── pdf-to-markdown-plan-zh.md
├── pyproject.toml
├── uv.lock
├── .python-version
├── config/
│   ├── chapters.json             # 内容单元、标题及页码映射
│   └── glossary.json             # 双语术语表
├── scripts/                      # 后续实施时创建的流程脚本
├── work/
│   ├── 01-inspection/            # PDF 盘点结果
│   ├── 02-input-batches/          # 按章节或页段拆分的 PDF
│   ├── 03-marker-output/          # Marker 原始 Markdown、图片和日志
│   ├── 04-normalized/             # 整理后的原文稿
│   ├── 05-translation/            # 翻译缓存、进度和问题记录
│   ├── 06-validation/             # 链接、锚点、覆盖率和抽样检查结果
│   └── progress.json              # 可恢复的阶段进度
├── docs/
│   ├── index-en.md
│   ├── index-zh.md
│   ├── 01-introduction/
│   │   ├── 01-introduction-en.md
│   │   ├── 01-introduction-zh.md
│   │   └── assets/
│   └── 02-foundations-of-language-modeling/
│       ├── 02-foundations-of-language-modeling-en.md
│       ├── 02-foundations-of-language-modeling-zh.md
│       └── assets/
└── reports/
    └── validation.json
```

命名规则：

1. 每个内容单元使用稳定的编号和英文短名作为目录名，例如 `01-introduction/`。
2. 同一内容的文件主名一致，英文文件名以 `-en.md` 结尾，中文文件名以 `-zh.md` 结尾。
3. 长章节可继续拆为编号小节，例如 `06-01-chain-of-thought-en.md` 与 `06-01-chain-of-thought-zh.md`，仍保存在所属章节目录。
4. 图片等资源放在章节的 `assets/` 子目录，由两种语言的 Markdown 使用相对路径引用。
5. 前言、附录、参考文献等内容也纳入章节映射，按相同规则生成双语文件。

正式稿以当前仓库的 `docs/` 为根目录，沿用 `00-front-matter/`、`01-introduction/` 等编号目录；`index-en.md` 和 `index-zh.md` 分别作为两种语言的总目录。若一个章节拆分为多个 Markdown 文件，在该章节目录内添加章节索引，按正文顺序链接到各小节。

## 3. 分阶段实施

| 阶段 | 工作 | 产物与完成条件 |
|---|---|---|
| 1. PDF 盘点 | 记录页数、书签、目录、文字层、扫描页及复杂表格/公式位置 | 章节清单和页码映射完整，所有页面均有归属或排除说明 |
| 2. 环境验证 | 通过 uv 创建环境、安装并锁定 Marker；在目标 Windows 硬件上确认推理后端可用 | 依赖可复现；一组普通页、公式页和表格页成功试转 |
| 3. 章节切分 | 根据书签和目录确定章节边界；长章再拆为若干页段 | 每个输入批次记录所属章节和 PDF 页码范围 |
| 4. Marker 提取 | 分批输出 Markdown，保留分页标记和提取图片；失败批次可单独重试 | 每批均有原始输出及日志，失败原因进入进度记录 |
| 5. 原文整理 | 合并同章批次、处理跨页段落和重复页、校正标题层级与资源链接 | 形成按章节保存、可回溯到来源页的原文稿 |
| 6. 双语生成 | 建立术语表，按章节或小节生成另一语言版本 | 中英文结构、标题和内容顺序一致，翻译疑点有记录 |
| 7. 验收 | 检查页码覆盖、章节顺序、双语文件、锚点、图片和内容抽样 | 通过验收清单并生成检查报告 |

先用一个含普通正文和复杂版面的代表章节完成完整试点，再确定批次大小和翻译流程，并据此处理其余内容。

## 4. Marker 提取与分批策略

Marker 的单文件命令提供 `--page_range`，可选择指定页或页段，输出目录和输出格式也可配置；分页输出可保留页码标记。Marker 命令行的页码从 `0` 开始，因此章节配置应明确区分从零开始的 PDF 页索引与从 1 开始的人工页码，避免偏移一页。

建议实施方式：

1. 优先按章节页段调用 Marker；较长章节可先用约 10–20 页作为试验批次，再根据试转速度、内存和版面连续性调整。
2. Marker 每批输出到独立目录，使用 Markdown 格式并保留分页标记和图片。先根据数字 PDF 的文字层质量选择 `fast` 或 `balanced`，不要预先对全部页面强制 OCR。
3. 对扫描页、乱码页、公式或表格质量不足的页面单独复核，再决定是否针对这些页启用 OCR/更高质量模式。
4. 批次边界尽量落在段落或小节边界。遇到跨页表格或段落时，可增加少量重叠页；合并时依据页码和文本内容去重。
5. 保留 Marker 原始输出。清理、修复和翻译均写入后续阶段目录，避免覆盖原始材料。
6. 记录 PDF 原始页索引与书中印刷页码的对应关系；索引链接应使用验证过的章节内锚点或页锚点。

## 5. 目录导航和链接映射

章节目录使用稳定的编号和英文短名，因此中英文目录项始终映射到同一章节目录；语言版本通过文件后缀区分。总目录分别指向对应语言的章节文件，章节文件顶部提供回到本语言总目录的链接，并可链接到相邻章节及同一章节的分段文件。

- 每个总目录项必须对应实际存在的目标文件；中英文目录项数量、顺序和章节编号一致。
- 分段章节的章节索引按阅读顺序链接到全部片段，并提供前一段、后一段及回到章节索引的链接。
- 标题锚点使用 Markdown 标题生成规则；遇到中文标题、重复标题或渲染器差异时，为目标标题显式设置稳定锚点，并在中英文稿中维持对应关系。
- 页码链接采用显式 `page-<PDF零基页索引>` 锚点；不能假定 Marker 的分页分隔符自动生成可跳转锚点。整理阶段写入锚点，校验阶段确认每个页码链接都有目标。
- 图片使用相对于章节 Markdown 文件的路径；中英文稿引用同一份图片时，路径必须在两份文件所在位置均可解析，或在生成时分别写入正确的相对路径。
- 自动校验所有本地 Markdown 链接、文件目标、片段锚点和资源路径；报告列出源文件、链接文本和缺失目标，修复后重新运行。

官方参考：[Marker README：单文件转换和命令行参数](https://github.com/datalab-to/marker#convert-a-single-file)。Marker 的 Markdown 输出支持图片链接、表格、LaTeX 公式和代码块；实际效果仍需用样章核验。

## 6. 中英文内容规则

先判断 PDF 的主要语言。原文语言版本作为校对后的基准稿，另一语言以章节或完整小节为单位翻译。若原文为英文，则输出 `-en.md` 原文稿和 `-zh.md` 中文译稿；若原文为中文，则对应输出中文原文稿和英文译稿。

- 保留公式、代码、数字、链接、引用编号和文献标识；翻译前可对这些内容作占位保护，翻译后逐项还原检查。
- 标题、正文、图表标题、脚注和列表均纳入翻译范围，不以摘要替代原文。
- 维护统一的中英术语表；重要术语首次出现时可附英文原词。
- 文献作者、DOI、URL 和原始文献标题原则上保留原样。
- 公式或图像中无法可靠识别的内容标记为待核对，不凭上下文补写。
- 记录翻译工具或服务、版本、日期、术语表版本和失败段落；机器翻译稿应经过人工审阅后再作为定稿。

## 7. Python 与依赖管理（uv）

后续实施时用 uv 管理项目环境和 Python 包，不使用裸 `pip install` 修改项目环境。

1. 以项目实际兼容性确定并固定 Python 版本，写入 `.python-version`。
2. 在 `pyproject.toml` 声明直接依赖；Marker 的 PDF 包为 `marker-pdf`。仅在实际流程需要时再加入 PDF 盘点、Markdown 检查或翻译相关依赖。
3. 通过 `uv add` 添加依赖并生成/更新 `uv.lock`，将锁文件纳入版本控制；通过 `uv sync --locked` 按锁文件安装。
4. 使用 `uv run --locked ...` 执行转换、整理和校验命令，确保运行时不悄悄改变锁文件。
5. 先在目标 Windows 环境试装 Marker 及其 PyTorch/推理依赖，再锁定兼容组合。Marker 官方说明要求 Python 3.10+，并说明不同设备使用的推理后端不同；具体后端、驱动和资源占用须在试点阶段验证。
6. 记录 Marker 发布版本或固定提交，不依赖未锁定的主分支，以便重建相同环境。

参考：[Marker 安装和推理后端说明](https://github.com/datalab-to/marker#installation)、[uv 项目指南](https://docs.astral.sh/uv/guides/projects/)、[uv 同步与锁文件](https://docs.astral.sh/uv/concepts/projects/sync/)。

## 8. 进度恢复和质量控制

`work/progress.json` 记录 PDF 哈希、Marker 版本、运行配置、章节编号、页段、批次输出、阶段状态、重试次数及错误摘要。重新执行时只处理失败或输入已变化的批次；原文有改动时重新检查相应译文和链接，不重复运行无关批次。

验收至少覆盖以下内容：

- 所有 PDF 页面已映射到内容单元，页段无遗漏、错序和未说明的重复。
- 每个内容单元都有对应的 `-en.md` 和 `-zh.md`，文件位于独立章节目录。
- 目录链接、章节导航、页锚点及图片路径均可解析。
- 标题层级、公式、表格、代码块、脚注和引用经抽样核对；章节开头、结尾及批次交界处重点检查。
- 两种语言的章节顺序和结构可对应；数字、单位、公式、引用和专有名词无意外变化。
- 所有待核对内容列入问题清单，未解决的章节不标记为验收完成。

## 9. 主要风险和应对

| 风险 | 应对 |
|---|---|
| PDF 页码与目录页码不一致 | 维护页码映射，并以 PDF 实际页索引进行 Marker 分批 |
| 章节边界落在页面中间 | 根据页内标题和段落拆分内容块，抽查边界页，必要时使用上下文重叠 |
| 扫描页、公式或表格提取质量不稳定 | 样章覆盖复杂页面；针对问题页复核并调整 OCR/转换模式 |
| 翻译遗漏或术语不一致 | 按小节记录进度，运行双语覆盖检查并维护术语表，安排人工审阅 |
| Windows 上推理依赖或硬件不兼容 | 在全文处理前完成本机安装与资源试验，固定验证通过的 Python、Marker 和后端组合 |
| 中断后无法判断完成范围 | 按批次写入进度清单和独立输出，允许失败批次单独重跑 |

## 10. 建议实施顺序

按“盘点 → 安装验证 → 单章试点 → 调整章节和批次配置 → 分批提取 → 原文校对 → 双语生成 → 自动与人工验收”的顺序推进。每完成一个阶段先检查其产物，再开始依赖该产物的下一阶段；若样章暴露出结构或依赖问题，先修正规则并重新验收样章。

## 11. Marker 命令模板（实施时使用）

下面仅作为后续实施的命令模板，本方案阶段不执行转换。先通过 `uv run marker_single --help` 核实已锁定版本支持的参数，再根据章节配置替换页码和输出目录：

```powershell
uv run marker_single .\AgenticLargeLanguageModels.pdf `
  --page_range "0-19" `
  --output_format markdown `
  --paginate_output `
  --output_dir .\work\03-marker-output\01-introduction\batch-01
```

Marker README 中 `--page_range` 的示例采用从 `0` 开始的 PDF 页索引；示例页段 `0-19` 因此指 PDF 的前 20 页。每个批次指定独立输出目录，保留原始结果，再由后续整理流程写入正式章节目录。设备模式、OCR 和并行选项应先用样章测定，再纳入锁定的运行配置。

本方案依据项目 README 当前列出的单文件转换参数编写，参数可能随 Marker 版本变化；实施时以锁定版本的 `--help` 输出和对应版本文档为准：[Marker 项目 README](https://github.com/datalab-to/marker#convert-a-single-file)。
